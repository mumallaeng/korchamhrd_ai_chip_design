## 현재 수업과 연결

- 현재 수강 노트에는 직접 비중 있게 다뤄지지 않았다.
- 이후 testbench 정리나 반복 로직 정리에서 중요해질 가능성이 높다.

## 핵심 요약

- 함수와 태스크는 반복되는 코드를 묶어 재사용하기 위한 도구지만, 둘의 역할은 다르다.
- 함수는 하나의 값을 반환하고 simulation time을 소비하지 않는 계산 블록에 가깝다.
- 태스크는 여러 입력과 출력을 다루고, timing control도 포함할 수 있으므로 testbench 절차를 묶는 데 특히 적합하다.
- RTL 안에서는 간단한 조합 계산을 함수로 분리하는 경우가 많고, testbench에서는 stimulus나 check 절차를 태스크로 묶는 경우가 많다.
- 이 장은 코드 중복을 줄이기 위한 문법 소개가 아니라, `어디까지 추상화해도 회로 의미가 흐려지지 않는가`를 판단하는 장으로 보는 편이 좋다.

## 이 장에서 반드시 남길 메모

- 함수는 `식처럼`, 태스크는 `절차처럼` 쓴다고 정리한다.
- timing control 허용 여부를 함수/태스크 비교표로 적는다.
- 현재 강의에서는 아직 비중이 작으므로, testbench 정리 시 다시 불러올 장으로 표시한다.
