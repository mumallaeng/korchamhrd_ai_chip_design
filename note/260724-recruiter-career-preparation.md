## 지원 서류에서 확인할 근거

지원 서류는 공고가 요구하는 형식과 항목을 정확히 따른다. 지원 직무, 기간, 학력·경력 날짜, 자격·어학 성적의 유효 상태, 회사·기술 명칭을 다시 확인하고 표기 방식도 일관되게 유지한다. 교육 과정과 프로젝트 수행 과정이 평가 근거에 포함되는 곳도 있으므로, 이력서뿐 아니라 학습 태도, 출결, 프로젝트 산출물, 발표 자료를 함께 관리한다.

| 확인 항목 | 정리 기준 |
| :--- | :--- |
| 지원 직무 | 공고의 직무명과 지원서 표기를 일치시킨다. |
| 기간·날짜 | 프로젝트·교육·경력의 시작과 종료를 사실대로 적는다. |
| 기술 명칭 | tool, language, board, protocol 이름을 실제 사용 범위에 맞춘다. |
| 자격·어학 | 유효 기간과 성적 정보를 제출 전에 확인한다. |
| 제출 형식 | 파일명, PDF 여부, 포트폴리오 link, 추가 서류 요구를 다시 확인한다. |

## 지원 동기와 직무 선택

지원 동기는 `왜 이 회사인가`, `왜 이 직무인가`, `내 경험이 그 직무 준비와 어떻게 이어지는가`를 하나의 흐름으로 설명한다. 먼저 JD의 업무와 요구 역량을 읽고, 수업·프로젝트에서 쌓은 구체적인 경험을 연결한다. 현재 지원하는 직무를 선택한 이유와 그 직무에서 더 쌓고 싶은 역량을 분명히 적는다.

## 프로젝트와 포트폴리오

프로젝트는 결과물 이름만 나열하지 않는다. 목표, 기간, 사용 기술, 본인 역할, 직접 결정하거나 해결한 문제, 검증 방법, 결과를 분리해 짧게 정리한다. 같은 교육과정을 들은 지원자 사이에서는 팀 전체 결과보다 본인이 맡은 범위와 기여 근거가 차이를 만든다.

| 항목 | 면접에서 설명할 내용 |
| :--- | :--- |
| 목표 | 어떤 문제를 해결하려 했는가 |
| 구조 | block·interface·data flow가 어떻게 연결되는가 |
| 본인 역할 | 직접 설계·작성·debug·검증한 범위 |
| 문제와 판단 | 어떤 문제가 있었고 어떤 근거로 해결했는가 |
| 검증 | simulation, waveform, board, log 중 무엇으로 확인했는가 |
| 결과 | 목표 대비 완성 범위와 남은 제한 사항 |

다른 팀 결과에서 배운 내용은 자신의 직접 기여와 분리해서 적는다. 신입 포트폴리오는 문제를 이해하고 개선한 과정과 성장 가능성을 보여 준다. 이력서와 포트폴리오의 모든 문장은 후속 질문에 일관되게 설명할 수 있어야 한다.

## 자기소개서와 면접

자기소개서는 면접 질문의 근거가 된다. 자신 있게 설명할 수 있는 프로젝트, 협업, 문제 해결 경험을 중심으로 쓰고, 실제로 하지 않은 일은 넣지 않는다. 모르는 질문에는 아는 범위, 판단 근거, 확인 방법을 구분해 답한다.

발표형 면접은 제한 시간 안에 끝내는 것을 요구사항으로 본다. 발표 자료를 실제 제한 시간에 맞춰 여러 번 연습하고, 핵심 메시지와 보조 설명을 구분한다. 입실부터 퇴실까지의 태도, 자세, 시선, 인사도 준비 범위에 포함한다. 동료와 면접관·지원자 역할을 나누어 연습하면 말의 길이와 질문 대응을 점검할 수 있다.

## 실무 학습과 AI 활용

`SystemVerilog/UVM`은 verification testbench의 중심 language다. Python은 대용량 simulation 결과와 log를 parsing하고, 반복 작업에서 원하는 정보를 추출하는 automation script에 유용하다. 언어를 학습할 때에는 사용 위치를 함께 구분한다.

| 영역 | 중심 도구·언어 | 준비 방향 |
| :--- | :--- | :--- |
| RTL 설계 | Verilog·SystemVerilog | hardware structure와 interface를 설명한다. |
| verification | SystemVerilog·UVM | transaction, driver, monitor, scoreboard, coverage 흐름을 설명한다. |
| automation | Python·shell | 반복 simulation, log parsing, 결과 정리를 자동화한다. |
| system·firmware | C·C++ | register, driver, embedded software와 hardware 경계를 이해한다. |

생성형 AI 사용 범위는 회사 보안 policy와 승인된 환경에 따라 정해진다. 학습에서는 AI output을 그대로 제출하지 않고, 요구사항 충족 여부를 판단하고 비교·검증하는 데 사용한다. 구현 방법의 trade-off와 검증 근거를 본인이 설명할 수 있어야 한다.

UVM은 최소 동작 environment를 먼저 이해하고, 기본 구조를 유지한 채 sequence, driver, monitor, scoreboard, coverage를 하나씩 추가하는 순서로 학습한다. 큰 기능을 한 번에 넣기보다 작은 변경마다 compile·simulation·waveform을 확인한다.

## 영어와 지원 커뮤니케이션

영어 점수 기준은 공고와 회사에 따라 확인한다. 글로벌 환경에서는 교육, 공지, tool, 문서가 영어일 수 있으므로, 점수와 함께 업무 문서를 읽고 기본 의사소통을 할 수 있는 능력이 기회를 넓힌다.

이메일 지원에서는 인사, 지원 포지션, 지원 이유, 첨부 자료를 명확히 적는다. 지원 지침을 정확히 따르고, 회사와 직무를 조사한 신뢰할 수 있는 근거를 준비한다. 제출한 자료는 말로 다시 설명할 수 있도록 반복 연습한다.
