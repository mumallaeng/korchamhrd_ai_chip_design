## 전체 흐름

```text
현재 수업
  → VGA 수업 (약 2주)
  → VGA 프로젝트 (VGA 수업 종료 직후, 짧은 규모)
  → VGA 프로젝트 발표 (9월 8일~10일)
  → 최종 프로젝트 착수
```

VGA 수업이 끝나는 대로 곧바로 VGA 프로젝트에 들어가고, 9월 8일~10일 사이 발표가 끝나는 시점에 맞춰 최종 프로젝트로 넘어가는 일정으로 안내되었다. 최종 프로젝트 준비 기간은 과거 기수 기준으로 3~4주가 걸렸던 사례를 근거로 잡은 값이다.

최종 프로젝트의 팀 구성(대형)은 이번 수업 시점에는 확정되지 않았고, 담당 교수가 참여하는 다음 수업에서 다시 논의하기로 했다. [최종 프로젝트 방향](260626-axi-timer-uart-microblaze-interrupt.md)은 지금까지 배운 AI 활용·FPGA board·custom IP·peripheral 제어를 조합하는 큰 틀을 유지하되, 팀 구성과 구체 주제는 이번 공지 이후 순서로 확정한다.

## VGA 수업 목표와 실습 준비

이번 VGA 수업은 카메라 영상을 모니터에 띄우고 그 위에 필터 등 영상 처리를 적용하는 것을 최종 목표 예시로 잡고, 화면에 그림이 나타나는 원리를 처음부터 배우는 과정이다. 실습을 위해 VGA 출력을 HDMI로 변환하는 컨버터 케이블을 인원수만큼 배부했다. 최근 모니터는 VGA 입력 단자가 없는 경우가 많아 이 변환 케이블이 필요하며, 실제 연결은 이론 설명 이후에 진행하기로 했다.

## CRT(Cathode Ray Tube) 디스플레이 원리

옛날 브라운관 TV·모니터에 쓰인 소자는 CRT(Cathode Ray Tube, 음극선관)다. CRT라는 이름은 이 발광 현상을 처음 실험한 Braun(브라운)의 이름에서 왔고, 한국에서는 흔히 "브라운관"이라고 부른다.

```text
가열 코일(heater)
  → 음극(cathode)에서 전자 방출
  → 편향판(deflection plate) 통과, 걸린 전압에 따라 진행 경로가 휨
  → 형광물질(phosphor) 코팅된 화면에 충돌
  → 충돌 지점에서 빛 발생
```

| 구성 요소 | 역할 |
| :--- | :--- |
| 전자총(electron gun) | 전자를 가속시켜 화면 쪽으로 쏘는 부분 |
| 음극(cathode) | 코일 가열로 전자를 방출하는 극 |
| 편향판(deflection plate) | 전압으로 전자빔의 진행 경로를 휘게 해 화면 위 도달 위치를 결정 |
| 형광물질(phosphor) | 전자가 충돌하면 빛을 내는 화면 코팅 물질 |

코일에 열을 가하면 음극에서 전자가 방출되고, 이 전자는 편향판 사이 전압에 이끌려 진행 경로가 휘면서 화면 위 특정 위치로 향한다. 그 위치의 형광물질에 전자가 부딪히면 빛이 나며, 편향판 전압을 조절해 전자빔이 부딪히는 위치를 바꿔가는 방식으로 화면에 한 점씩 그림을 그린다.

전자총에서 나온 전자는 가속 양극(accelerating anode)을 거치며 속도가 붙고, 이후 좌우를 담당하는 호리젠탈(horizontal) 편향판과 상하를 담당하는 버티칼(vertical) 편향판을 차례로 통과한다. 편향판은 사실상 전자석이라, 흐르는 전류의 크기로 자기력 세기를 조절해 전자빔이 휘는 각도를 정한다. 화면이 완전한 평면이 아니라 살짝 볼록한 이유도 여기서 나온다. 전자총에서 화면 중앙까지의 거리와 화면 가장자리까지의 거리가 평면이면 서로 달라지는데, 화면을 볼록하게 만들면 중앙이든 가장자리든 전자총에서 형광면까지의 거리가 같아져 빔이 도달하는 시간과 초점이 균일해진다.

## VGA 타이밍 신호: Sync와 Porch

CRT는 아날로그 소자라 전류를 갑자기 끊어도 즉시 0이 되지 않고, 충전된 만큼 서서히 방전된다. 그래서 전자빔이 한 줄을 다 그리고 다음 줄의 맨 왼쪽으로 되돌아가려면(retrace), 편향 코일 전류가 원래 값으로 복귀할 여유 시간이 필요하다. 이 복귀 구간을 화면 타이밍에 미리 반영해 둔 것이 VGA 신호의 porch다.

```text
[Back Porch] → [Display(활성 라인)] → [Front Porch] → [Sync] → (다음 라인 Back Porch로 반복)
```

| 구간 | 의미 |
| :--- | :--- |
| Display | 실제 화면에 보이는 픽셀이 그려지는 구간 |
| Front Porch | 활성 화면이 끝난 직후, sync 신호 전까지의 여유 구간 |
| Sync (H-Sync/V-Sync) | 전류가 0이 되는 구간, 줄 또는 프레임의 끝과 시작을 구분하는 기준 신호 |
| Back Porch | sync 신호가 끝난 뒤, 다음 활성 화면이 시작되기 전까지의 여유 구간 |

porch라는 이름은 서양 주택의 현관 앞 공간(porch)에서 따온 표현으로, 안으로 들어가기 직전의 여유 공간이라는 뜻을 신호 앞뒤의 마진에 그대로 빌려 쓴 것이다. H-Sync는 각 라인의 좌우 시작점을, V-Sync는 프레임의 첫 번째 라인 시작점을 알려주는 기준 신호 역할을 하며, 이 기준이 없으면 수신 쪽이 화면의 어디부터 그려야 할지 알 수 없다.

교재 그림에서 흔히 보는 "Display가 맨 앞, Front Porch·Sync·Back Porch가 뒤"의 순서는 실제 신호가 무한 반복되는 흐름 중 사람이 계산하기 편한 지점(Back Porch 직후, Display 시작점)을 0,0 기준으로 다시 잡아서 그린 것이다. 실제 하드웨어 신호 자체는 Back Porch → Display → Front Porch → Sync 순으로 계속 반복된다.

VGA `640×480` 표준은 화면에 보이는 해상도일 뿐이고, 실제 신호 타이밍은 porch와 sync를 포함해 수평 `800px`, 수직 `525`라인 기준으로 맞춘다. 화면은 초당 60번(60Hz) 갱신된다.

## 수평/수직 타이밍 세부값과 픽셀 클럭

`640×480@60Hz` 표준의 구간별 실제 값은 다음과 같다.

| 구분 | Display | Front Porch | Sync | Back Porch | 합계 |
| :--- | ---: | ---: | ---: | ---: | ---: |
| 수평(픽셀) | 640 | 16 | 96 | 48 | 800 |
| 수직(라인) | 480 | 10 | 2 | 33 | 525 |

한 프레임을 초당 60번 그리려면 필요한 픽셀 클럭은 `800 × 525 × 60 ≈ 25.2MHz`다. 이 클럭 기준으로 한 라인을 그리는 데 필요한 시간은 약 `31.77µs`(그중 실제 디스플레이 구간은 약 `25.17µs`)이고, 한 프레임 전체는 약 `16.78ms`(그중 실제 디스플레이 구간은 약 `15.25ms`)가 걸린다.

## Basys3 VGA 커넥터와 RGB444

Basys3 보드의 VGA 커넥터는 R·G·B 각 색상 신호를 저항 네트워크(DAC 역할)로 내보내는 핀과 H-Sync·V-Sync 핀으로 구성된다. 각 색상 채널은 4비트 디지털 값을 저항 네트워크에 통과시켜 `0~3.3V` 사이의 아날로그 전압으로 바꾸는 방식으로 밝기(강도)를 표현하며, 4비트라 채널당 16단계의 밝기를 낼 수 있다. R·G·B 세 채널 모두 4비트씩 쓰기 때문에, 우리가 실습에서 쓰는 색 표현 방식은 RGB444다.

## R-2R 저항 사다리형 DAC

FPGA가 만들어내는 4비트 디지털 값을 VGA가 요구하는 아날로그 전압으로 바꾸는 회로는 저항을 층층이 연결한 저항 사다리(R-2R ladder) 구조다. 비트 위치가 하나 올라갈 때마다 저항값이 2배씩 커지고, 걸리는 전압은 같은 채로 흐르는 전류가 절반씩 줄어드는 방식으로 비트별 기여도가 이진 가중치(1, 2, 4, 8…)를 갖게 만든다. 각 비트의 전류를 모두 합치면 4비트 값 하나가 `0~3.3V` 범위의 전압 한 단계에 대응되며, R-2R 사다리는 이런 DAC 구조 중 가장 단순한 형태다.

## VGA는 클럭선 없는 신호: H-Sync·V-Sync만으로 동기화

VGA 신호에는 주소선도 클럭선도 없다. 모니터와 FPGA 보드는 각자 내부에서 같은 픽셀 클럭(25MHz) 기준으로 독립적으로 동작하며, H-Sync로 "한 라인이 끝났다", V-Sync로 "한 프레임이 끝났다"는 사실만 서로에게 알려준다. 보드가 픽셀 값을 순서대로 계속 내보내면 모니터도 자기 내부 타이밍에 맞춰 순서대로 그 값을 찍어나가는 구조라, 두 장치가 동기화된 것처럼 동작한다. 클럭선 없이 각자의 내부 타이밍만으로 맞춰 돌아간다는 점에서 UART의 비동기 통신과 개념적으로 비슷하다. 반대로 LCD·LED 같은 디지털 패널은 클럭선을 별도로 준다.

## 카운터 기반 타이밍 생성 설계

VGA 타이밍은 주소 대신 두 개의 카운터로 만든다.

| 카운터 | 역할 | 범위 | 비트 폭 |
| :--- | :--- | :--- | :--- |
| H-Count | 픽셀 클럭(25MHz)마다 1 증가, 한 라인 안에서의 가로 위치 | `0~799` | 10비트 |
| V-Count | H-Count가 799에서 0으로 돌아갈 때마다 1 증가, 라인 위치 | `0~524` | 10비트 |

픽셀 클럭 25MHz는 시스템 클럭 100MHz를 4분주(100MHz ÷ 4)해서 만든다. H-Count·V-Count 값을 그대로 X, Y 좌표로 쓸 수 있고, 두 카운터 값을 비교기로 판단해 Sync와 Display Enable 신호를 만든다.

```text
H-Sync 활성(Low)   : (Display+Front Porch) ≤ H-Count < (Display+Front Porch+Sync)
Display Enable = 1 : H-Count < 640  AND  V-Count < 480
```

V-Sync도 같은 방식으로 V-Count 값을 그 프레임의 sync 구간과 비교해서 만든다. Display Enable이 0인 구간(porch·sync 구간)에서는 RGB 출력을 내보내면 안 된다.

## 실습: 스위치로 RGB444 직접 출력 (VGA_Decoder·VGA_RGB_SW·VGA_SW_Top)

오늘 만든 회로는 화면에 실제 이미지 대신 스위치로 지정한 단색을 채우는 실습이다.

| 모듈 | 역할 |
| :--- | :--- |
| VGA_Decoder | 픽셀 클럭 분주, H/V 카운터, Sync·Display Enable·X,Y 좌표 생성 |
| VGA_RGB_SW | 보드 스위치 값을 그대로 R·G·B 4비트씩에 1:1로 매칭해 픽셀 값 생성 |
| VGA_SW_Top | 위 두 모듈을 묶어 클럭·리셋·스위치를 입력받고 H-Sync·V-Sync·RGB를 출력하는 최상위 모듈 |

스위치 입력값이 그대로 각 채널의 밝기가 되어, 값이 낮을수록 어둡고 높을수록 밝은 색이 출력된다. 이 실습은 화면 전체를 단색으로 채우는 것이 목적이라 X, Y 좌표는 실제로 쓰지 않고, Display Enable 신호로 porch·sync 구간에만 출력을 끄는 것만 사용한다.

## 다음 단계 예고: X,Y 좌표로 화면 영역 나눠서 색 지정

스위치로 단색을 채우는 실습 다음 단계는, `VGA_Decoder`가 만들어주는 x_pixel·y_pixel 좌표값을 이용해 화면을 여러 영역으로 쪼개고 영역별로 다른 색을 출력하는 것이다. 픽셀 데이터 값을 스위치가 아니라 그 순간의 (x, y) 좌표에 맞춰 바꿔주면 화면 위치별로 다른 색이 나타나며, 이 방식은 이후 최종 프로젝트에서도 자주 쓰일 예정이라고 안내했다.

수업은 이 지점에서 잠시 쉬는 시간을 가진 뒤 이어가기로 했다.
