# 26-MM-DD - 핵심 주제 요약 (기술/실습 수업용)

이 파일은 골격 예시다. 실제 노트를 쓸 때는 이 구조를 복사해서 값만 채우고, 이 설명 문단들은 지운다.

## 작성 규칙

- 표 셀 끝에는 `~한다`, `~된다`, `~이다` 같은 완결형 어미를 쓰지 않는다. `~함`, `~확인`, `~결정`, `~기준`, `~흐름`, `~사용`처럼 명사형으로 끝내고 마침표를 붙이지 않는다.
- 본문 문장은 서술형(`~한다`, `~된다`)으로 쓴다.
- `녹화`, `녹음`, `전사`, `STT`, `SRT`, `자막`, `PDF 요약`, `PDF 흐름` 같은 캡처·처리 과정 단어를 본문에 남기지 않는다. 실제 개념 설명으로 바꿔 쓴다.
- 분·타임스탬프 단위 진행 로그를 만들지 않는다. 개념 중심으로 재구성한다.
- 코드/명령/신호/레지스터/파일 경로는 backtick으로 감싼다.

## 골격

```markdown
# 26-MM-DD - 핵심 주제 요약

관련 노트:

- [26-MM-DD - 이전 관련 노트 제목](이전-노트-파일명.md)
- [도메인 지도 노트 제목](도메인-지도-파일명.md)

> 수업일: `2026-MM-DD`
>
> 현재 상태: 오늘 다룬 범위와 다음 수업에서 이어질 지점을 한두 문장으로 요약한다.

## 수업 범위

| 구분 | 내용 |
| :--- | :--- |
| 주제 1 | 핵심 내용 |
| 주제 2 | 핵심 내용 |

## 전체 흐름 (선택)

\`\`\`text
단계 1
  → 단계 2
  → 단계 3
\`\`\`

## 개념 섹션 제목

개념 설명 본문. 배경 → 원리 → 실제 적용 순서로, 서술형 문장으로 쓴다.

\`\`\`text
구조 또는 데이터 흐름 다이어그램
\`\`\`

| 표 제목 | 설명 |
| :--- | :--- |
| 항목 | 명사형 설명 |

(개념 섹션은 다룬 주제 수만큼 반복한다. 기록 순서가 아니라 개념 단위로 묶는다.)

## 실습 확인 항목

- 확인 항목 1
- 확인 항목 2

## 환경 점검 (선택, 실습·디버깅이 있었던 날만)

| 증상 | 확인 순서 | 처리 기준 |
| :--- | :--- | :--- |
| 증상 설명 | 확인 명령/절차 | 최종 조치 |
```
