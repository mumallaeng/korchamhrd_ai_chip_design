## 공통 원칙

| 항목 | 정리 |
| --- | --- |
| 설계 흐름 | `설계 -> testbench -> simulation -> synthesis -> implementation -> bitstream` 순서로 본다. |
| 조합논리 | `assign` 또는 `always @(*)`로 작성하고, 모든 경우를 빠짐없이 처리한다. |
| 순차논리 | `always @(posedge clk)` 계열로 작성하고 상태 갱신은 보통 `<=`를 쓴다. |
| 자료형 감각 | `wire`는 연결, `reg`는 절차 블록 변수다. `reg`가 곧 하드웨어 레지스터라는 뜻은 아니다. |
| XDC | 포트 이름, 핀 번호, I/O standard가 정확히 맞아야 한다. |
| 검증 | 보드에 바로 올리기 전에 파형으로 먼저 확인한다. |
