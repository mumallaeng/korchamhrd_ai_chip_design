# 26-04-06 전반부 - 개발환경과 Vivado 흐름

## 한눈에 보기

| 항목 | 내용 |
| --- | --- |
| 목표 | Vivado 프로젝트 구조와 기본 설계 흐름을 먼저 익힌다 |
| 핵심 | `Design Sources`, `Simulation Sources`, `Constraints`를 분리해서 본다 |
| 결과 | `프로젝트 생성 -> 소스 추가 -> 시뮬레이션 -> 합성 -> 비트스트림` 흐름을 잡는다 |

| 파일 | 위치 | 의미 |
| --- | --- | --- |
| `helloHDL/260406_gates/gates.srcs/sources_1/new/gates.v` | `1-23` | 가장 단순한 design source 예시 |

## 프로젝트 구조

| 구분 | 의미 | 여기서 보는 것 |
| --- | --- | --- |
| `Design Sources` | 실제 회로가 되는 RTL | `gates.v` |
| `Simulation Sources` | DUT를 검증하는 TB | `tb_gates.v` |
| `Constraints` | 핀, I/O standard, 보드 연결 정보 | `gates.xdc` |

## 기본 흐름

```text
프로젝트 생성
-> RTL 추가
-> TB 추가
-> XDC 추가
-> Run Simulation
-> Open Elaborated Design
-> Run Synthesis
-> Run Implementation
-> Generate Bitstream
```

## 이 날 꼭 잡아야 하는 것

| 항목 | 정리 |
| --- | --- |
| top module | 보드 핀과 직접 만나는 최상위 모듈 |
| simulation top | DUT를 감싸는 testbench |
| elaborated design | 코드를 파싱해 RTL 구조로 펼쳐 본 결과 |
| synthesis | RTL을 실제 게이트 구조로 바꾸는 단계 |
| bitstream | FPGA에 다운로드하는 최종 결과물 |

## 주의점

| 실수 | 정리 |
| --- | --- |
| 소스 파일만 넣고 TB를 안 만든다 | 기능 확인이 안 된다 |
| XDC 없이 구현까지 간다 | 보드에서는 핀이 연결되지 않는다 |
| simulation과 synthesis를 같은 것으로 본다 | 둘은 목적이 다르다 |
