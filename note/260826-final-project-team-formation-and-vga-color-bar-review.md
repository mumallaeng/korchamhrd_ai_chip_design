프로젝트 주제 선정이 평가에서 가장 중요한 요소라고 강조했다. 주제가 점수의 절반 이상을 차지하며, 완성도가 같아도 너무 흔한 주제는 인상이 떨어지고 새롭고 재미있는 주제일수록 창의성 점수가 올라간다고 조언했다. 팀이 꾸려지면 식사·쉬는 시간에 틈틈이 주제를 논의해보라고 권했다.

## VGA 컬러바 실습 리뷰 (강사 시연)

지난 시간 과제였던 [SMPTE 컬러바](260825-vga-crt-timing-rgb444-counter-sync.md)를 강사가 직접 구현하며 설계 흐름을 리뷰했다. 스위치 입력 없이 `de`·`x_pixel`·`y_pixel`만 받아서 RGB를 출력하는 구조는 동일했다.

- 화면을 세로로 3구간(길이가 서로 다른 상단 컬러바·중간 반전바·하단 PLUGE)으로 나누고, `y_pixel < 320` 같은 비교로 구간을 판별했다.
- 상단 구간은 가로 7색, 하단 구간은 8개 조각(4칸 + 3분할 + 나머지)으로 나눴다.
- 가로 분할은 640픽셀을 7등분한 91픽셀 단위를 기준으로 잡았고, 하단 4칸째 경계도 같은 91픽셀 단위를 이어서 썼다.
- 색상은 R·G·B 각 자리를 1(켜짐)/0(꺼짐)으로 미리 표를 만들어두고 조합하는 방식(예: 화이트 = `111`)으로 정리했다.
- 구간 경계값(라인 수·픽셀 수)은 학생마다 조금씩 다르게 잡아도 문제없다고 확인해줬다 — 정확한 표준 수치와 안 맞아도 3단·7분할 구조 자체가 맞으면 정답으로 인정한다는 취지였다.

## VGA 출력 안정화: 조합회로 글리치와 출력 레지스터(VGA_OutReg)

컬러바/스위치 mux 회로를 완성한 뒤, 지금 구조에 남아있는 개선 여지를 짚었다.

- **전력 관점**: 스위치 모드로 화면을 보고 있어도 컬러바 계산 회로, 컬러바 모드일 때도 스위치 계산 회로가 둘 다 항상 계속 동작(조합회로라 입력이 있으면 끊임없이 재계산)하고 있다는 점을 지적했다. 진짜 저전력 회로로 만들려면 안 쓰는 쪽에는 클럭을 아예 넣지 않는 방식(클럭 게이팅)이 필요하지만, 지금 설계는 그 개선을 적용하지 않은 상태라고 확인해줬다.
- **글리치(glitch) 문제**: mux 출력까지 이어지는 경로가 전부 조합회로라서, 회로가 비동기적으로 동작한다 — 즉 입력(카운터 값 등)이 바뀌면 그 즉시, 신호 경로마다 전파 속도가 조금씩 달라 값이 안정되기 전까지 나노초 단위의 아주 짧은 순간 원치 않는 스파이크(글리치)가 출력에 섞여 나갈 수 있다는 점을 짚었다. 사람 눈에는 안 보이지만, 이런 글리치가 그대로 H-Sync·V-Sync·RGB 출력 핀까지 나가는 건 디지털 회로 설계상 좋지 않은 습관이라고 강조했다.
- 조합회로 경로가 계속 길어지면 타이밍 클로징에서 네거티브 슬랙(제한 시간 내에 계산이 못 끝나는 상태)이 발생할 수 있다는 점도 함께 짚었다 — 그래서 회로 중간중간에 레지스터(파이프라인 스테이지)를 끼워 넣는 게 일반적인 관행이라고 설명했다.

**해결책 — 출력단에 레지스터(파이프라인) 한 단 추가**: mux 직후에 `VGA_OutReg`라는 모듈을 하나 더 붙여서, H-Sync·V-Sync·RGB 세 신호를 클럭 엣지에 맞춰 동시에 래치한 뒤 내보내도록 했다. 글리치는 클럭이 들어오기 전 대기 구간에서 발생했다가 사라지고, 클럭이 딱 걸리는 순간에는 이미 안정된 값만 레지스터에 저장되므로 출력 핀에는 안정된 값만 나간다는 원리다. 이 출력 레지스터는 화면 타이밍용으로 분주한 픽셀 클럭이 아니라 시스템 클럭(100MHz) 그대로를 사용해서 동작한다.

## 메모리 기반 이미지 출력: 2차원 좌표 → 1차원 주소 변환

컬러바처럼 계산으로 그리는 대신, 미리 저장된 그림을 그대로 화면에 출력하는 방법으로 넘어갔다. 그림은 픽셀 하나하나의 RGB 값이 메모리(ROM)에 저장돼 있는데, 메모리는 본질적으로 1차원이라 2차원 `(x, y)` 좌표를 하나의 주소로 바꿔야 한다.

- 변환 공식: `주소 = 640 × y + x` (640은 VGA 가로 해상도) — 한 라인이 끝나고 다음 라인으로 넘어갈 때마다 시작 주소가 정확히 640씩 밀리는 구조다.
- 예: `(100, 100)` 픽셀의 주소는 `640×100 + 100 = 64100`.
- 오늘 컬러바에서 쓰던 것과 같은 `x_pixel`/`y_pixel`로 이 주소를 계산해 메모리에 넣으면 그 위치의 픽셀 데이터(색상 값)가 나온다.
- 픽셀 데이터 폭은 16비트를 쓴다. `de`(Display Enable)가 0인 구간(porch·sync)에서는 메모리에서 읽은 값 대신 무조건 0을 내보내야 한다 — 컬러바·스위치 실습 때 `de`로 게이팅했던 것과 같은 원리다.

## 실습: Lena 이미지를 메모리 데이터(C 파일)로 변환

전통적인 영상처리 샘플 이미지인 "Lena"를 실습 소재로 썼다. 원래 1970년대 잡지 화보 사진이었는데 초기 영상처리 연구자가 별다른 이유 없이 골라 논문에 쓴 것이 계속 인용·재사용되며 영상처리 분야의 고전 표준 테스트 이미지가 된 사연을 설명했다 — 다만 출처 문제로 요즘은 학회에서 잘 안 쓰는 추세라 오해하지 말라는 당부도 함께 했다.

실습 절차:

1. 위키백과 등에서 Lena 원본 이미지를 다운로드한다.
2. 무료 이미지 편집 프로그램으로 4:3 비율로 잘라서 `640×480` 크기로 저장한다.
3. `ezBMP` 변환 프로그램으로 이 이미지를 불러와 RGB 16비트(RGB565) 형식으로 변환한다 — 출력 결과에는 8비트 버전과 16비트 버전이 같이 들어있어 16비트 쪽을 골라 써야 한다.
4. 변환된 데이터를 다시 C 파일로 저장하는 것으로 실습을 마무리한다.

## RGB 포맷 비교와 RGB565 → RGB444 변환

컬러 포맷을 정리했다.

| 포맷 | 비트 폭 | 채널별 비트 | 주 용도 |
| :--- | :--- | :--- | :--- |
| RGB888 | 24비트 | R8·G8·B8 | 일반 PC 모니터 등 고해상도가 필요한 환경 |
| RGB565 | 16비트 | R5·G6·B5 | 차량 내비게이션 등 임베디드 소형 디스플레이 |
| RGB444 | 12비트 | R4·G4·B4 | 지금 실습 중인 VGA 출력 |

실무에서 가장 많이 쓰는 건 RGB888과 RGB565 두 가지라고 짚었다. 지금 프로젝트는 Lena 이미지가 RGB565(16비트)로 저장돼 있는데 출력은 RGB444(12비트)라서, 각 채널의 상위 4비트만 잘라 쓰는 방식으로 변환한다 — R(5비트)·G(6비트)·B(5비트) 각각에서 위쪽 4비트만 취하고 나머지 하위 비트는 버린다.

## 실습: Image ROM과 ROM Reader 만들기

- 기존에 만든 `VGA_Decoder`, mux, `VGA_OutReg`(파이프라인 레지스터)는 그대로 재사용한다.
- 새로 만들어야 하는 건 두 가지: 이미지 데이터를 담는 **Image ROM**과, `x_pixel`/`y_pixel`로 주소를 계산해 ROM에서 픽셀 데이터를 읽어오는 **ROM Reader**다.
- Vivado IP 카탈로그에서 Block Memory Generator를 추가해서 이미지 ROM을 만들고, 앞서 변환해둔 Lena 데이터 파일로 초기값을 채운다.
- ROM 깊이(주소 개수)는 `640 × 480 - 1`만큼 필요하다 — 크기를 `640×380` 등으로 잘못 잡으면 바로 에러가 난다는 주의를 줬다.
- 어드레스·데이터·H-Sync/V-Sync 신호는 각각 wire로 선언해서 모듈 간에 연결해야 한다.

수업은 이 지점에서 학생들이 직접 타이핑해서 만들어보는 실습 시간으로 넘어갔다.

## QVGA로 이미지 데이터 줄이기

`640×480` RGB565 이미지 전체를 FPGA 내부 ROM에 저장하면 필요한 용량은 다음과 같다.

```text
640 × 480 × 16bit = 4,915,200bit
```

Basys3의 내부 Block RAM 용량으로는 이 데이터를 모두 담기 어렵기 때문에 원본 이미지의 가로와 세로를 각각 절반으로 줄여 `320×240` QVGA 이미지로 만들었다. 가로와 세로가 각각 절반이 되므로 픽셀 수와 ROM 용량은 원래의 1/4이 된다.

```text
320 × 240 × 16bit = 1,228,800bit
```

이미지 편집 단계에서 해상도를 `320×240`으로 변경하고, 변환된 RGB565 데이터를 다시 `img.mem`으로 준비한다. ROM 깊이와 주소 계산식도 실제 데이터 크기와 동일하게 맞춰야 한다.

```systemverilog
logic [15:0] mem [0:320*240-1];
assign addr = y_pixel * 320 + x_pixel;
```

`img.mem`은 240개 행에 각 행당 320개의 RGB565 값이 배치된 구조다. 이미지 데이터만 줄이고 주소 계산에 기존 가로 폭 `640`을 남겨두면 화면 좌표와 ROM의 행 경계가 일치하지 않는다.

## VGA 화면에서 QVGA 이미지가 반복되는 이유

출력 타이밍은 여전히 `640×480` VGA 좌표 전체를 생성하지만 ROM에는 `320×240` 픽셀만 존재한다. 이 상태에서 VGA의 `x_pixel`과 `y_pixel`을 그대로 주소 계산에 사용하면 유효한 QVGA 범위를 벗어난 뒤에도 주소를 계속 만든다. 그 결과 ROM 데이터가 다시 읽히거나 행 경계가 어긋나 동일한 그림이 여러 번 반복된 것처럼 보인다.

수업에서는 QVGA 이미지 한 장만 왼쪽 위에 표시하고 나머지 VGA 영역은 검은색으로 만드는 방법을 먼저 적용했다.

```systemverilog
logic display_area;
logic display_area_d;

assign display_area = de &&
                      (x_pixel < 320) &&
                      (y_pixel < 240);

assign addr  = display_area ? (y_pixel * 320 + x_pixel) : 0;

always_ff @(posedge clk or posedge reset) begin
    if (reset)
        display_area_d <= 1'b0;
    else
        display_area_d <= display_area;
end

assign o_rgb = display_area_d
             ? {px_data[15:12], px_data[10:7], px_data[4:1]}
             : 12'b0;
```

`display_area`는 현재 VGA 좌표가 QVGA 이미지 범위 안에 있는지를 나타낸다. 범위 안에서는 ROM 주소와 RGB 값을 사용하고, 범위를 벗어나면 RGB에 `0`을 출력해 검은색으로 표시한다.

동기식 ROM은 주소를 넣은 클럭의 다음 사이클에 `px_data`가 나오므로 현재 좌표에서 만든 `display_area`를 그대로 RGB mux에 사용하면 제어 신호와 픽셀 데이터의 시점이 한 클럭 어긋난다. 따라서 `display_area`도 플립플롭 한 단을 통과시킨 `display_area_d`를 사용해 ROM 출력과 시간을 맞춘다.

### 한 장을 작게 표시하는 방법과 화면에 꽉 채우는 방법

두 방식은 ROM 데이터는 같지만 화면 좌표를 ROM 주소로 바꾸는 방법이 다르다.

| 표시 방식 | 주소 계산 | 결과 |
| :--- | :--- | :--- |
| QVGA 원래 크기 | `y_pixel * 320 + x_pixel` | 왼쪽 위 `320×240`에 한 장을 표시하고 나머지는 검은색 처리 |
| VGA 전체 확대 | `(y_pixel >> 1) * 320 + (x_pixel >> 1)` | 원본 픽셀 하나를 가로·세로 각각 두 번 사용해 `640×480` 전체에 표시 |

화면 전체 확대에서는 `(0,0)`, `(1,0)`, `(0,1)`, `(1,1)`의 네 화면 픽셀이 동일한 ROM 픽셀 `(0,0)`을 읽는다. 별도의 보간 연산 없이 픽셀을 `2×2`로 복제하는 nearest-neighbor 확대 방식이다.

## 같은 ROM 코드가 BRAM과 LUT로 달라지는 이유

강의에서는 `image_rom`의 읽기 방식을 바꾼 뒤 합성 자원 사용량을 비교했다. 메모리 배열과 `$readmemh` 초기화는 같아도 읽기 코드가 동기식인지 비동기식인지에 따라 Vivado가 추론하는 실제 하드웨어가 달라진다.

### 동기식 읽기

```systemverilog
always_ff @(posedge clk) begin
    data <= mem[addr];
end
```

- 클럭 엣지에서 주소에 해당하는 데이터를 출력 레지스터에 저장한다.
- 출력은 주소보다 한 클럭 늦게 나온다.
- Vivado가 Basys3의 전용 Block RAM으로 추론할 수 있는 형태다.
- 강의 화면의 합성 결과에서는 BRAM 사용량이 약 72%로 나타났다.

### 비동기식 읽기

```systemverilog
assign data = mem[addr];
```

- 주소가 바뀌면 조합회로 경로를 통해 데이터가 바로 바뀐다.
- 한 클럭 지연은 없지만 FPGA Block RAM의 일반적인 동기식 읽기 구조와 맞지 않는다.
- 같은 이미지 배열이 Block RAM 대신 LUT 기반 분산 메모리 또는 조합 논리로 구현될 수 있다.
- 강의 화면의 비교 결과에서는 BRAM 사용이 사라지는 대신 LUT 사용량이 약 77%까지 증가했다.

따라서 코드상으로는 `always_ff`를 `assign`으로 바꾼 한 줄 차이지만, 합성 후에는 'BRAM에 저장된 ROM'과 'LUT로 구성된 ROM'이라는 서로 다른 하드웨어가 된다. 큰 이미지에는 동기식 BRAM 구조가 적합하며, 한 클럭 지연은 `display_area_d`처럼 주변 제어 신호를 같은 수만큼 지연시켜 맞춘다.

## XDC와 외부 포트 제약

RTL 소스만 프로젝트에 넣고 XDC를 추가하지 않으면 합성·배치·배선은 진행되더라도 비트스트림 생성 직전 DRC에서 실패한다. `clk`, `reset`, VGA RGB, H-Sync, V-Sync와 같은 모든 top-level 외부 포트에는 Basys3 핀 위치와 `IOSTANDARD`가 지정돼야 한다.

반대로 XDC에 활성화된 포트가 top module에 없으면 `No ports matched`와 `'set_property' expects at least one object` 경고가 발생한다. 이번 이미지 출력 top에서 사용하지 않는 `sw_red`, `sw_green`, `sw_blue` 제약은 주석 처리하고 실제 사용하는 VGA 출력 제약만 활성화한다.
